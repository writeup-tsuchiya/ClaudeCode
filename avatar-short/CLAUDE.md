# avatar-short — プロジェクトの憲法

縦型ショート動画（1080x1920 / 30fps / 30〜60秒）を、顔写真1枚・自己紹介ドキュメント・参照音声から自動生成する。

**採用構成（2026-08-16 決定）**: 自己紹介動画 / 0円構成
`Irodori-TTS` ＋ `SadTalker` ＋ `Manim`（既定）／`HyperFrames`（退避）

正典は `docs/REQUIREMENTS_avatar-short.md`。この CLAUDE.md と食い違ったら**要件定義書が正**。

---

## 0. 最初に守ること

```
・exit 0 を完了と見なさない。成果物を ffprobe 等で測ってから報告する
・推測した数値を書かない。測った値か、測っていないことを明記する
・失敗したら、その工程だけやり直せる形にする
・見た目の値は設定ファイルに出す（コードに直接書かない）
```

**「エラーは出ていないが成果物が無い／中身が空」は実際に起きる。** 必ず実物を測る。

---

## 1. 役割分担

> **判断はエージェント、処理は単機能のコマンド。**

エージェントがやるのは「何を喋らせるか」「どの情報を画面に出すか」という**判断**だけ。
音声合成・リップシンク・描画・合成・検査は、引数を受け取って結果を返すコマンドに切り出してある。

**測定をエージェントにやらせない**（§8-6）。`ffprobe` → 音量 → 口元切り出し → フレーム抽出…という配管に
ターンを使い切って判定前に止まる事故が3回起きた。配管は `tools/verify_short.py` に入っている。
エージェントの仕事は `verify.json` を読んで**合否を言うこと**だけ。

---

## 2. 工程（この順序を変えない）

```
photo.jpg + intro.md + voice_ref.wav
  ① brief    自己紹介docを読み、話者プロフィールJSONに整える     ← エージェント
  ② script   台本と、画面に出す情報を決める                   ← エージェント
  ③ face     写真の検品                        tools/check_face.py
  ④ voice    本人の声を複製して台本を読ませる     tools/make_voice.py
  ⑤ avatar   ④の音声で写真の口を動かす          tools/make_avatar.py
  ⑥ slides   資料の層を焼く                    tools/make_slides.py
  ⑦ compose  1本にまとめる                     tools/compose.py
  ⑧ verify   機械で検査                        tools/verify_short.py
  ⑨ deliver  納品                                                ← エージェント
```

🔴 **④→⑤ の順序は絶対に変えない。** 先に声を作り、**その音声で口を動かす**。
逆にするとアバター側の合成音声になり、本人の声でなくなる。
`make_avatar.py` は `voice/out.wav` が無ければ**実行を拒否する**（コードで止めてある）。

## 3. 1本 = 1ディレクトリ

```
runs/<slug>/
├── brief.json       ①の出力
├── script.json      ②の出力
├── timeline.json    ④で実測してから start/end を埋める（台本の文字数から推測しない）
├── face.json        ③の出力
├── voice/
│   ├── chunks.json  チャンクごとの実測尺
│   ├── ref.latent.pt 参照音声のエンコード結果（使い回す・§6-6）
│   └── out.wav      ④の出力
├── avatar.mp4       ⑤の出力
├── slides.mp4       ⑥の出力（不透過・1080x1920・30fps）
├── final.mp4        ⑦の出力
├── verify.json      ⑧の出力
└── verify_frames/   ⑧の出力
```

途中で失敗しても、その工程だけ再実行できる。

## 4. エンジンの切り替え

⑥の**入口は `make_slides.py` 1つ、出口は必ず `slides.mp4`**。
だから ⑦compose と ⑧verify は、どちらのエンジンで焼いても1行も変えなくてよい。

```bash
python3 tools/make_slides.py --run runs/<slug>                      # 既定（Manim）
python3 tools/make_slides.py --run runs/<slug> --style night-tech    # 見た目を変える
python3 tools/make_slides.py --run runs/<slug> --engine hyperframes  # 退避エンジン
```

🔴 **同じ契約の実装を2つ持つ**のが設計の要点。新しい道具を試すときは**戻り道を先に作ってから**試す。

## 5. 決定論（再現しない動画を作らない）

- 時計・乱数・ネットワーク・無限リピートを使わない
- 🔴 **Python 組み込みの `hash()` を使わない。** 文字列の `hash()` はプロセスごとに変わる（`PYTHONHASHSEED`）。
  「乱数を1行も使っていないのに焼くたびに変わる」という、いちばん原因を追いにくい形になる。
  → 振り分け・キャッシュキーは `hashlib`。`tools/common.py` の `stable_index()` / `rotation()` を使う。
- 見た目の振り分けは**プールの長さと互いに素な数だけ回す**（`rotation()`）。
  独立したハッシュで振ると「たまたま3段続けて同じ背景」が普通に起きる。
  互いに素方式なら**隣が必ず異なり、プールを1周する**ことが構造的に保証される。
- 判定: 2回焼いて `ffmpeg ... psnr` が 40dB 以上（`verify_short.py --psnr-against`）

## 6. 画面に出すもの

🔴 **要点テロップだけを出す。ナレーション逐語の字幕帯は出さない**（2026-08-14 決定）。
テロップが内容を伝えているので二重になるし、字幕帯は図の層と場所を取り合う。

**変えるなら `.claude/agents/video-evaluator.md` の must_pass 7 も同時に変える。**
片方だけ変えると、仕様どおりの成果物が不合格になる。

---

## 7. 他人の顔と声（技術より先に守る）

- **顔とは別に、声の同意が要る。** 「写真をもらった」は「声を複製してよい」ではない
- `assets/people/<person-id>/consent.json` が無い person-id では**生成しない**（コードで止めてある）
- **自動で公開しない。** 外に出す操作は毎回確認を取る
- **自己紹介ドキュメントに書いていないことを喋らせない**（経歴を盛らない）
- `assets/people/` は git に入れない（`.gitignore` 済み）

---

## 8. 長時間の処理

⑤avatar は実時間の 7〜18倍かかる。10分を超える処理は切り離して実行する。

```bash
bash tools/run_bg.sh <ログ名> <コマンド...>
# → logs/<ログ名>.log と logs/<ログ名>.exit が出る
```

- **`python3 -u`（バッファなし）で走らせる。** 付けないと途中で止まったときログが0バイトになる
- **完了判定はプロセスの生死ではなくファイル（`.exit`）の出現で行う**

## 9. 却下の記録の書き方

「その理由が効く条件」まで書く。条件が変わっても引き継がれてしまう。

```
× SadTalker は遅いので使わない
⭕ SadTalker は実時間の183倍。10分動画=30時間なので この用途では使わない（尺が短ければ成立しうる）
```

倍率のような線形に効く数字は、条件を変えたときの再計算に使える資産になる。
記録は `wiki/` に置く。

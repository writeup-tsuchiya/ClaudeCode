# Manim の縦向きレンダは3段構えで壊れる（検査をすり抜ける形で）

**症状**: `--resolution 1080,1920` を渡して焼いた `slides.mp4` が、
`ffprobe` では 1080x1920 と出るのに、中身は横向きの絵が中央に置かれ上下が黒帯だった。

🔴 **§2 の判定基準1「出力が 1080x1920 である」を満たしてしまう。**
コマンドの終了コードも 0。**目視（§2-5）で初めて見つかった。**

---

## 原因は3つ、別物だった

### 1. `-qh` が `--resolution` を上書きする

Manim の品質プリセット `-qh` は **1920x1080（横向き）** を意味する。
`--resolution 1080,1920` と併記すると `-qh` が勝つ。

→ **品質プリセットを渡さない。** 解像度と fps は `--resolution` / `--fps` で明示する。

### 2. `--resolution` はピクセル数だけ変え、シーンの座標系を追随させない

実測（manim 0.21.0）:

```
$ manim render --resolution 1080,1920 ...
PROBE pixel=1080x1920 frame=14.222x8.000 fps=30.0
                            ^^^^^^^^^^^^ 16:9 のまま
```

`config.frame_width` を `frame_height * pixel_width / pixel_height` に直す必要がある。

### 3. 直す場所を間違えると、絵が画面の3割の大きさになる

`Scene.setup()` の中で `config.frame_width` を直しても遅い。
カメラはすでに古い `frame_width` で倍率を決めている。

実測: 1080 / 14.222 = **75.9 px/単位** のまま。
frame_height=8 単位が 8 × 75.9 = **607px** にしかならず、
1920px の画面の中央に 31.6% の大きさで置かれた。

→ manim CLI は「config を解釈 → シーンのモジュールを import → Scene を作る」の順に動く。
**モジュールの読み込み時**に直せば間に合う。

---

## 対処

`tools/manim_scene.py` の `_fit_frame_to_pixels()` をモジュール直下で呼ぶ。
`tools/engines/manim_engine.py` は `-q` を渡さない。

## 効く条件

- manim 0.21.0 / manimpango 0.6.1 で実測。
- 3番は「カメラが構築される前に config を直す必要がある」という一般則なので、
  Manim のバージョンが上がっても形は変わりにくい。
- 1番と2番は Manim 側が直す可能性がある。**上げたら測り直すこと。**

## この件から引ける教訓

**`ffprobe` の寸法だけでは「正しく焼けた」は言えない。**
⑧verify が `verify_frames/*.png` を必ず出すのはこのため。
機械で測れるのは寸法までで、**中身が縦向きに組まれているかは人が見るしかない。**

# 音量測定が「無音に近い」と誤って出た — 正規表現が途中経過を拾っていた

**症状**: `verify.json` の音量が **-70.0 LUFS**。ほぼ無音という値。
実際の音声は正常だった。

**原因**: `ffmpeg -af ebur128` は**再生中の途中経過も、末尾のサマリーと同じ書式で出す**。

```
[Parsed_ebur128_0 @ ...] t: 0.1  M: -70.0 S: -70.0  I: -70.0 LUFS  ← 冒頭（まだ無音）
...
Summary:
  Integrated loudness:
    I:         -14.6 LUFS                                          ← これが答え
```

`re.search`（＝最初の一致）を使っていたので、**冒頭の -70.0 を拾っていた**。

**対処**: `Summary:` 以降だけを見て、`re.findall` の最後の一致を取る。
`verify.json` に `_source` として、Summary から取れたのかどうかも残す。

**効く条件**: ffmpeg の `ebur128` フィルタ全般。バージョンに依らない。

## この件から引ける教訓

**測定コマンドの出力を「最初の一致」で読まない。**
進捗を出すフィルタは珍しくない。同じ形は `silencedetect` や `psnr` でも起こりうる。

そして、この誤りは**測定コマンドを人が読む形でしか出していなかったら気づけなかった**。
数値を JSON に落として、目標値と並べて表示していたから
「-70.0 LUFS（目標 -16.0±3.0 LU）」という**明らかにおかしい並び**が見えた。

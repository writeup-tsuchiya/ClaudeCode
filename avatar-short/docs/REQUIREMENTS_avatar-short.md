# 縦型ショート動画 自動生成エージェント — 要件定義書

**この1冊だけを新しい Claude Code に渡せば、ゼロから同じエージェントが作れる**ことを目的にした文書です。

> **読む人**: ハンズオン参加者と、その手元で動く Claude Code。
> **前提知識**: ターミナルでコマンドを1行貼れること。プログラミングの知識は要りません。
> **費用**: **基本構成は0円**（全部ローカルで動く無料ソフト）。有料の選択肢は §9 に分けて書きます。
>
> 🔴 **この文書に API キー・個人情報は一切含みません。** 各自が自分のマシンで用意します。

---

## 1. 作るもの

**顔写真1枚と自己紹介のドキュメントを渡すと、その人のアバターが喋る縦型ショート動画を1本、自動で作るエージェント。**

```
入力:  photo.jpg     顔写真1枚（正面・バストアップ）
       intro.md      自己紹介（箇条書きでも可）
       voice_ref.wav 本人の声 20〜30秒

出力:  final.mp4     1080x1920 / 30fps / 30〜60秒 / 音声つき
```

### 完成した動画の構成

```
┌─────────────────────────┐
│                    ┌──────┐ │ ← 右上に四角のワイプ
│                    │ 本人 │ │    （顔を検出して切り抜き）
│                    │の顔 │ │
│                    └──────┘ │
│                             │
│   ── 自己紹介               │ ← キッカー（小見出し）
│   山田 太郎                  │ ← 見出し
│   TARO YAMADA               │ ← サブ
│   株式会社サンプル            │ ← メタ
│                             │
│   （場面ごとに切り替わる）     │
└─────────────────────────┘
```

- **顔と口は本人**。写真1枚から、本人の声に合わせて口が動く
- **声は本人**。20〜30秒の参照音声から複製する
- **資料の層は動く**。背景・見出し・カードが順に現れて消える

### 🔴 1-2. まず構成を選ぶ（ここを飛ばさない）

このエージェントは**3つの層**でできています。**層ごとに道具を選びます。**

```
音声の層     ＝ 何の声で喋るか
アバターの層  ＝ 誰の顔が喋るか
資料の層     ＝ 画面に何を出すか   ← 動画の印象はここで決まる
```

#### ① 用途で決める

| | **自己紹介動画** | **解説動画** |
|---|---|---|
| 目的 | 人を憶えてもらう | 内容を理解してもらう |
| 主役 | **顔と声** | **図と流れ** |
| 資料の層 | 名前・肩書・要点のカード | **図が動いて説明する**（棒が伸びる・矢印がつながる） |
| **使う道具** | **HyperFrames**（文字の層）だけ | **HyperFrames ＋ Manim**（図の層を足す） |
| 尺の目安 | 30秒 | 60〜90秒 |

#### ② 予算で決める（層ごとに独立して選べます）

| 層 | **無料（0円）** | **有料に置き換えると** |
|---|---|---|
| **音声** | **Irodori-TTS** — 声の複製つき・ローカル | 商用TTS（文字数課金）。**無料でも声は複製できる**ので優先度は低い |
| **アバター** | **SadTalker** — 顔だけ動く | **HeyGen** $0.05/秒（60秒で$3）。**手ぶり・上半身も動く** |
| **資料** | **Manim（既定）** — 文字も図も動く。スタイルパックで見た目を切替 | 置き換え先なし |
| 資料（退避） | **HyperFrames** — HTML/CSS。Manim が合わないときに戻せる | 置き換え先なし |
| **映像素材** | （無し） | **MiniMax H3** $0.08〜0.13/秒。背景・B-rollを生成 |

🔴 **無料の組み合わせだけで完成します。** ハンズオンはこれで進めてください。
有料は「ここを置き換えると何が良くなるか」を知るための情報です。

#### ③ 迷ったらこれ

```
【自己紹介・0円】 Irodori-TTS ＋ SadTalker ＋ HyperFrames          ← ハンズオンの本線
【解説動画・0円】 Irodori-TTS ＋ SadTalker ＋ HyperFrames ＋ Manim
【手ぶりが要る】  上記の SadTalker を HeyGen に置き換える（有料）
【絵を足したい】  上記に MiniMax H3 の背景を足す（有料）
```

#### ④ 選ぶときの原則

🔴 **「AとBのどちらを使うべきか」と考える前に、役割が被っているかを確かめてください。**
被っていなければ答えは「両方」です。

```
MiniMax H3   → 絵そのものを生成する（背景・B-roll）      ※有料
Manim        → 図が動いて意味を説明する                 ※0円
HyperFrames  → 文字を指定どおり正確に組む               ※0円
SadTalker / HeyGen → 顔
```

⚠️ **生成AIの映像に日本語の文字を描かせないでください。** 崩れます。
**絵は H3、図は Manim、文字は HyperFrames** と分けます。

## 2. 完成の判定基準（これが満たせたら完成）

作った人が自分で確かめられる形にしています。**目視ではなくコマンドで測ってください。**

| # | 判定 | 測り方 |
|---|---|---|
| 1 | 出力が 1080x1920 である | `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 final.mp4` |
| 2 | 音声が入っている | 同上で `codec_type=audio` が1本あること |
| 3 | 尺が台本と一致する | 音声の尺と動画の尺の差が1秒以内 |
| 4 | 口が動いている | 口元だけを切り出して画素差を測る（**顔全体で測らない**・§10-6） |
| 5 | 文字が重なっていない | 各場面のフレームを1枚ずつ出して目視 |
| 6 | 同じ入力で同じ出力になる | 2回焼いて `ffmpeg ... psnr` が 40dB 以上 |

🔴 **`exit 0` を完了と見なさないでください。** 「エラーは出ていないが成果物が無い／中身が空」は実際に起きます。

## 4. 全体設計

### 4-1. 考え方

> **判断はエージェント、処理は単機能のコマンド。**

Claude Code（エージェント）がやるのは「何を喋らせるか」「どの情報を画面に出すか」という**判断**だけ。
音声合成・リップシンク・描画・合成は、**引数を受け取って結果を返すだけのコマンド**に切り出します。

こうする理由:

- **失敗した工程だけやり直せる**（毎回ゼロからにならない）
- **同じ入力なら同じ出力になる**（LLM に毎回 HTML を書かせると再現しない）
- **どこで失敗したか分かる**

### 4-2. 工程

```
photo.jpg + intro.md + voice_ref.wav
  ↓ ① brief     自己紹介docを読み、話者プロフィールJSONに整える      ← エージェント
  ↓ ② script    台本と、画面に出す情報を決める                    ← エージェント
  ↓ ③ face      写真の検品（顔が1つか・切れていないか）             ← コマンド
  ↓ ④ voice     本人の声を複製して台本を読ませる                   ← コマンド
  ↓ ⑤ avatar    ④の音声で写真の口を動かす                        ← コマンド
  ↓ ⑥ slides    資料の層（背景・文字・動き）を焼く                  ← コマンド
       └ 図の層  必要な段だけ、図解を透過動画で焼く（任意）           ← コマンド
                 入口は make_slides.py 1つ。エンジンは Manim / HyperFrames（§7-1）
  ↓ ⑦ compose   スライド＋アバターのワイプ＋音声を1本にする          ← コマンド
  ↓ ⑧ verify    尺・解像度・音量・口の動きを機械で検査              ← コマンド（§8-6）
  ↓ ⑨ deliver   納品（ファイル出力／チャットへ添付）                ← エージェント
```

🔴 **④→⑤の順序は絶対に変えないでください。**
先に声を作り、**その音声で口を動かします**。逆にすると、アバター側の合成音声になって本人の声でなくなります。

### 4-3. データの受け渡し（JSON契約）

```
brief.json  →  script.json  →  timeline.json  →  voice/out.wav
                                     ↓                 ↓
                              slides.mp4    ←    avatar.mp4
                                     └────┬────┘
                                       final.mp4
```

**1本 = 1ディレクトリ**（`runs/<名前>/`）。途中で失敗しても、その工程だけ再実行できます。

`timeline.json` の形（**④で実際の尺を測ってから埋める**。台本の文字数から推測しない）:

```json
{
  "person_id": "sample-taro",
  "total_sec": 28.0,
  "segments": [
    { "id": "s1", "start": 0.0, "end": 3.48,
      "narration": "こんにちは。サンプル株式会社の山田太郎です。",
      "telop": { "kicker": "自己紹介", "headline": "山田 太郎",
                 "sub": "TARO YAMADA", "meta": "株式会社サンプル" } },
    { "id": "s2", "start": 3.73, "end": 7.85,
      "narration": "...",
      "telop": { "kicker": "担当", "headline": "...",
                 "cards": [ { "t": "見出し", "d": "説明" } ] } }
  ]
}
```

## 6. ④voice — 本人の声で台本を読ませる

### 6-1. 使うもの（0円）

**Irodori-TTS**（日本語特化のローカル音声合成・**MIT ライセンス／商用可**）
HuggingFace: `Aratako/Irodori-TTS-500M-v3`

参照音声を渡すと**その声で読み上げます**。ローカルで動くので費用ゼロ、外部に音声を送りません。

### 6-2. 🔴 参照音声の作り方（ここで品質が決まる）

```
1. スマートフォンの純正イヤホンマイクで 20〜30秒（約100字）録音する
2. 言い直し・長い無音をカットする
3. ノイズ除去をかける（Adobe Podcast Enhance を2回など）
4. 48kHz・モノラル・約25秒 にして保存
```

🔴 **合成音声を参照に使わないでください。** 声の複製は**参照の声を写します**。
機械の声を写せば機械の声になります。「テストだから」と OS 付属の読み上げ音声を参照にして、
**「AIっぽい」という当然の結果**を出した実例があります。**確かめたいものが音質なら、参照は本物でなければ意味がありません。**

### 6-3. 導入

Irodori-TTS は **torch 2.10 系を要求します**。他の工程と共存できないので、**専用の環境**を作ります。

```bash
git clone https://github.com/Aratako/Irodori-TTS.git vendor/Irodori-TTS
cd vendor/Irodori-TTS && uv sync
```

### 6-4. 🔴 台本の書き方（音質に直結する）

| ルール | 理由（すべて実測） |
|---|---|
| **段落・文単位で分けて生成し、後で繋ぐ。長文を一括で渡さない** | **1回の生成は 30.0秒が上限**。193字を一括で渡すと予測31.4秒が30.000秒に切り詰められた。さらに一括は**約17%早口**になる（分割 5.50字/秒 に対し一括 6.43字/秒）。**壊れないので気づきにくい** |
| **漢字仮名交じりのまま入れる** | 全ひらがなにすると助詞「は」が `ha` と読まれる（実測で全40段落中4箇所） |
| **文末は「。」。「！」を使わない** | 文末「！」で声が 227Hz→526Hz（ほぼ1オクターブ）跳ねる事故が報告されている |
| **間は読点で作る** | 無音を差し込むのではなく読点で制御する |

**尺の見積り**: 実効 **約5.0〜5.3字/秒**。
→ **30秒 ≒ 160字 ／ 60秒 ≒ 320字**（他社TTSの 6.0字/秒 を流用すると1割ずれます）

### 6-5. 生成パラメータの基準値

```
--num-steps 40 --seed 333
--cfg-scale-text 3.0
--cfg-scale-speaker 1.0        ← 既定の 5.0 のままにしない
--cfg-guidance-mode independent
```

🔴 **`--cfg-scale-speaker` を既定（5.0）で使わないでください。**
参照音声の**話し方の癖まで引き継いで**文末が不自然になります。1.0 まで下げると**声質は保ったまま癖だけ抜けます**。

### 6-6. 速くするコツ

**参照音声のエンコードは1回だけにして使い回してください。** チャンクごとに毎回やると約1.7秒×チャンク数を捨てます。
実測: 18.98秒 → **13.06秒（31%短縮）**。出力は完全に同一です。

### 6-7. 読み間違いを二度と直さない仕組み

漢字の読み間違いは必ず起きます。**その場で台本を書き換えて済ませると、同じ発見を何度も繰り返します。**

```json
// config/yomi_dict.json
{ "entries": [
  { "id": "washa", "surface": "話者", "replace": "話し手",
    "reason": "「はなししゃ」と読まれる",
    "status": "approved", "verified_wav": "..." } ]}
```

- ④の直前に、この辞書を適用するコマンドを1本通す
- 🔴 **`status: approved` にするのは、人が実音声を聴いて直ったと確かめたときだけ。**
  推測で足した規則を自動で効かせると、**誤った規則が静かに積み上がります**

## 7. ⑥slides — 資料の層を作る

### 7-1. 🔴 入口は1つ、エンジンは2つ（0円）

```bash
python3 tools/make_slides.py --run runs/<slug>                      # 既定（Manim）
python3 tools/make_slides.py --run runs/<slug> --style <name>       # 見た目を変える
python3 tools/make_slides.py --run runs/<slug> --engine hyperframes # 旧エンジンに戻す
```

**出口は必ず `runs/<slug>/slides.mp4`**（不透過・1080x1920・30fps）。
だから **⑦compose と ⑧verify は、どちらのエンジンで焼いても1行も変えなくてよい**。

| エンジン | 何で書くか | 得意 | 立ち位置 |
|---|---|---|---|
| **Manim**（既定） | Python | 文字・図・グラフ・段階的な組み上げ | **本線** |
| HyperFrames | HTML / CSS / GSAP | 凝ったレイアウト・写真 | **退避**（Manim が合わない日に戻す） |

🔴 **同じ契約の実装を2つ持つ**のが設計の要点です。
片方が期待外れでも、**後段（合成・検査）を触らずに切り替えられます**。
新しい道具を試すときは、**戻り道を先に作ってから試してください。**

#### 見た目はスタイルパックで切り替える

配色・書体・背景のプールを `config/styles/*.json` に置き、`--style <name>` で選びます。
同梱の例: `pop-maru` / `kraft-mincho` / `night-tech`。

🔴 **段ごとの見た目の振り分けに、Python 組み込みの `hash()` を使わないでください。**
文字列の `hash()` は**プロセスごとに変わります**（`PYTHONHASHSEED`）。
「乱数を使っていないのに再現しない」という、**いちばん原因を追いにくい形**になります。→ `hashlib` を使う。

⚠️ **独立したハッシュで振り分けると「たまたま3段続けて同じ背景」が普通に起きます。**
プールの長さと**互いに素**な数だけ回す方式にすると、
**隣が必ず異なり、プールを1周する**ことが構造的に保証されます。

🔴 **画面に出すのは「要点テロップ」だけです。ナレーション逐語の字幕帯は出しません**（2026-08-14 決定）。
テロップが内容を伝えているので二重になりますし、字幕帯は図の層（§7-7）と場所を取り合います。
⑧verify の判定基準もこれに合わせてあります。
**逐語の字幕が要る用途に変えるなら、判定基準（`.claude/agents/video-evaluator.md` の must_pass 7）も
同時に変えてください。** 片方だけ変えると、仕様どおりの成果物が不合格になります。

### 7-2. 🔴 composition に必須の属性（1つでも欠けると動かない）

```html
<div id="root"
     data-composition-id="main"
     data-width="1080" data-height="1920"
     data-start="0" data-duration="28.0">
  <div class="clip" data-start="0" data-duration="3.48"> … </div>
</div>
<script>
  window.__timelines = window.__timelines || {};
  var tl = gsap.timeline({paused:true});
  // …動きの定義…
  window.__timelines["main"] = tl;   // ← キーは data-composition-id と一致させる
</script>
```

| 必須 | 忘れるとどうなるか |
|---|---|
| `data-composition-id` | タイムラインと結びつかない |
| `data-width` / `data-height` | 寸法が決まらない |
| **`data-start="0"`** | **再生が始まらない**（固まったように見える） |
| `class="clip"` + `data-start`/`data-duration` | その要素が**全編ずっと表示される** |
| フォントの `@font-face` | **別の書体で焼き上がる**（静かな劣化） |

**フォントは OS 同梱でも宣言が要ります。** しかも**フォントスタックに書いた実名フォント全部**に必要です:

```css
@font-face{font-family:"Hiragino Sans";src:local("Hiragino Sans");}
@font-face{font-family:"Hiragino Kaku Gothic ProN";src:local("Hiragino Kaku Gothic ProN");}
```

### 7-3. 🔴 焼く前に必ず lint を通す

```bash
npx --yes hyperframes@0.7.107 lint <compositionのディレクトリ>
```

レンダは1回10秒〜数分かかりますが、**lint は数秒で確定した答えを返します**。
実際に、書式の誤り5件が1回のlintで全部出ました。**レンダで試行錯誤しないでください。**

### 7-4. 決定論を守る（再現しない動画を作らないために）

- 時計・乱数・ネットワーク・無限リピートを**使わない**
- GSAP は `paused: true` のタイムラインを**1本だけ**作る
- GSAP は**ローカルに置いたファイル**を読む（CDN は落ちたとき黙って動きが消える）

### 7-5. HTML を LLM に毎回書かせない

**構造は生成スクリプト側に固定し、変わるのは `timeline.json` の中身と設定ファイルの値だけ**にしてください。
毎回自由に HTML/CSS を書かせると、**焼くたびに壊れ方が変わって原因を追えなくなります**。

### 7-6. 🔴 レンダが `page.goto` で固まるとき

HyperFrames は**内部で localhost にサーバを立て、そこへブラウザを繋いで**撮影します。
実行環境によっては、この接続が通らずタイムアウトします。

**確認**: 同じコマンドを**普通のターミナル**から実行してみてください。そこで通るなら、composition は正しく、
**実行している環境の制約**です。

**対処**: レンダだけを別の立場のプロセスに任せます。

```
自分 → composition を置き場に入れる
      ↓
常駐ワーカー（launchd の LaunchAgent）が拾って焼く
      ↓
自分 → 出来上がった mp4 を受け取る
```

キューは**ファイルの有無だけ**で管理します（`request` があれば未処理、`done` を書いたら完了）。
プロセス間の約束をファイルにしておくと、**どちらが落ちても状態が壊れません**。
`request` は**最後に置いてください**（中途半端な状態を拾わせないため）。

### 7-7. 図の層（Manim）— 図が動いて説明する段だけ足す

⑥には層が2つあります。**両方いる／役割が違う**ので、どちらかを選ぶ問題ではありません。

| 層 | 道具 | 担当 | 苦手 |
|---|---|---|---|
| 文字の層 | HyperFrames | 文字組み・レイアウト。日本語の折り返しも書体もそのまま | 図形の変形・数量の対応づけ |
| 図の層 | **Manim**（MIT・0円） | 図が動いて意味を説明する。棒が伸びる・矢印がつながる・注目部分に寄る | 折り返しは Pango 任せで**文節を知らない** |

🔴 **2026-08-14 訂正**: 以前ここに「Manim にテロップを描かせない（自動折り返しが無いから）」と書いていましたが、
**誤りでした**。`MarkupText` は Pango 経由で日本語を折り返します（`manimpango` の `pango_width` / `alignment` も公開引数）。
現在は **Manim を⑥の既定エンジンにする**方針で作り替え中です。

**使い方**

```bash
bash tools/setup_manim.sh                                       # 専用の venv を作る
python3 tools/make_manim_cut.py --run runs/<slug>               # 図の層を焼く
python3 tools/make_manim_cut.py --run runs/<slug> --print-args  # ⑦へ渡す引数を出す
```

図は `timeline.json` の `diagram`（**任意**）から作ります。無い段は今までどおりです。

```json
{
  "id": "s3",
  "telop": { "kicker": "しくみ", "headline": "毎朝ここに届く" },
  "diagram": { "template": "flow", "items": ["集める", "まとめる", "届ける"], "region": "lower" }
}
```

型は6つ用意してあります。**LLM に毎回コードを書かせないでください**（HTML と同じ理由です）。

| 型 | 絵 | 向く場面 |
|---|---|---|
| `timeline` | 縦の軸が伸び、節目が順に立つ | 経歴・沿革 |
| `counter` | 数字が0から数え上がる | 実績の数量 |
| `bars` | 横棒が順に伸びる | 比較・割合 |
| `flow` | 箱が現れ矢印でつながる | 手順・仕組み |
| `compare` | 左右2枚を並べ、片方を立てる | 対比 |
| `reveal` | 全体を見せ、注目する1つ以外を薄くする | 今どこの話か |

🔴 **導入で1箇所だけ詰まります。** `pycairo` は macOS 向けの完成品を配布しておらず必ずソースから
組み立てるので、`pkg-config` が要ります。

```bash
brew install pkgconf     # cairo は既に入っていることが多い。pango と LaTeX は不要
```

**🔴 図とテロップは同じ場所を取り合います。** `diagram` のある段では、
`cards` / `quotes` を出さず、テロップを画面上部に寄せる作りにしてあります。
**合成してみるまでこの衝突は見えません。** ⑧verify で必ずフレームを見てください。

## 8. ⑤avatar と ⑦compose

### 8-1. ⑤avatar に使うもの（0円）

**SadTalker**（写真1枚＋音声から喋る顔を作る・**Apache 2.0／非商用制限は撤回済み**）

> **「古いから劣る」ではありません。** 候補5つを比べたところ、
> **商用可 × macOS 対応**の両方を満たすのはこれだけでした（他は非商用ライセンス、または CUDA 前提で macOS の記載なし）。
> 🔴 **性能を比べる前に、ライセンスと動作環境で候補を絞ってください。** 直せない制約から先に見ます。

### 8-2. 🔴 Apple GPU を使うための3つの改修（全部当てないと動かない）

そのまま入れると **CPU だけで動き、5.9倍遅くなります**。3つとも「MPS が非対応」に見えるエラーを出しますが、
**Apple GPU 側の問題ではありません**。

| # | 症状 | 実際の原因 | 対処 |
|---|---|---|---|
| 1 | GPUが使われない（遅いだけで動く） | `inference.py` の分岐に **CUDA しか無い** | 分岐に `mps` を足す |
| 2 | `Conv3D is not supported on MPS` | **指定された torch(2.2.2) が未実装**。新しい torch では動く | **新しい torch の別環境**を作る |
| 3 | `invalid type: 'torch.mps.FloatTensor'` | **旧API `.type(文字列)` が MPS を知らない** | 型文字列を dtype/device に翻訳する |

🔴 **1番が当たっていないと、`mps` を指定しても黙って CPU で走ります。**
「GPUにしても速くならなかった」という**誤った結論**になるので、**実行前にパッチの適用を確認するコマンドを1本入れてください。**

⚠️ **`PYTORCH_ENABLE_MPS_FALLBACK=1` は効きません。** Conv3D は明示的にエラーを投げるため、fallback の対象外です。

**効果の実測**:

| 構成 | 実時間に対する倍率 | 60秒の動画 |
|---|---|---|
| CPU のみ | 104.7倍 | 1時間45分 |
| **Apple GPU** | **17.8倍** | **約18分** |

> torch を新しくしただけでは 1.4% しか変わりません（103.2倍）。**速さは全部 GPU の寄与**で、
> 新しい torch は「GPU を使えるようにするための前提条件」です。

### 8-3. 🔴 入力画像は「出力でどう見えるか」で決める

**写真を小さくすると、全体が劇的に速くなります。**

| 入力画像 | 倍率 | 28秒の動画 |
|---|---|---|
| 800x1200 | 17.8倍 | （換算 8分） |
| **1024x1024** | **7.1倍** | **3分19秒** |

理由: 最後の「元サイズへ貼り戻す」工程が**画素数に比例**し、**全体の3分の2を占める**からです。
**ワイプに 281px でしか映らないなら、それ以上の解像度で計算した分は丸ごと捨てています。**
→ **元がきれいだから大きいまま渡す、は誤りです。**

### 8-4. 顔の切り抜き

**顔を検出してから切ってください。** 目分量で切ると写真ごとにずれます。

🔴 **OpenCV の標準検出（Haar）で「いちばん大きい検出＝顔」としないでください。**
実測で、**顔ではなく「顔＋胴体」を囲む誤検出のほうが大きく**、それを採用した結果
**顎から下だけが写る動画**が黙って出来上がりました。
→ SadTalker が同梱している **RetinaFace**（`detection_Resnet50_Final.pth`）を使ってください。
同じ写真で検出1件・確度 1.000 でした。**追加のダウンロードも不要です。**

### 8-5. ⑦compose（ffmpeg）

```
背景（スライド動画）
  ＋ 右上に四角のワイプ（アバターを正方形に切って縮小・枠線つき）
  ＋ 音声（アバター動画から取る。別に足すと二重になる）
  → 1080x1920 / 30fps / H.264 + AAC
```

- ワイプの位置とサイズは**引数で変えられるように**しておく（必ず調整が入ります）
- 枠線は `drawbox` で描けます（`drawtext` と違い、たいていのビルドに入っています）

## 8-6. 🔴 ⑧verify は「コマンド」にする（エージェントに測らせない）

検査もエージェントにやらせたくなりますが、**測定はコマンドに寄せてください。**

**実際に起きたこと**: 検査担当のエージェントが**3回続けて、判定を出す前に turn 上限で止まりました。**
測定自体は毎回正しいのに、`ffprobe` → 音量測定 → 黒フレーム検出 → 口元の切り出し → フレーム抽出…という
**配管に turn を使い切っていた**のです。

🔴 **上限を上げても、ターン配分を指示しても直りませんでした。**
理由は単純で、**エージェントは自分の残りターン数を知りません。**
「残り5ターンになったら切り上げろ」は、**本人が知り得ない情報に依存した指示**でした。

**直し方**: 配管を1本のコマンドに移し、**エージェントの仕事を「測定」から「判断」に変える。**

```bash
python3 tools/verify_short.py --run runs/<slug>
→ runs/<slug>/verify.json ＋ verify_frames/*.png
```

コマンドが測り切って JSON に落とし、**エージェントはその JSON を読んで合否を言うだけ**にします。

⚠️ **検査コマンドは合否で終了コードを変えないでください。**
「測れた／測れなかった」だけを終了コードにします。合否は判断であり、判断はエージェントの仕事です。
ここを混ぜると、**不合格のたびに自動化が異常終了**します。

## 10. 落とし穴集（すべて実際に踏んだもの）

### 10-1. 古いソフトには古い依存がある。新しくすれば安全、ではない

- **Python は 3.10 でなければ動きません。** 依存の中でいちばん狭い制約が `scikit-image==0.19.3` で、
  arm64 macOS 向けのビルドが **3.10 用しか存在しません**
- **`setuptools` を最新に上げてはいけません。** バージョン81以降は `pkg_resources` を同梱しなくなり、
  古いライブラリが起動時に落ちます。`setuptools<81` に固定してください
- **`torch` は先に入れてください。** 一部のパッケージはビルド時に torch を読み込むため、
  同時に入れると「torch が無い」で失敗します

### 10-2. エラーメッセージの主語を、そのまま原因として読まない

`... is not supported on MPS` は**MPSのせいに読める書き方**をしていますが、実際の原因は
①コードが選択肢を持っていない ②ライブラリの版が古い ③APIの世代が古い、と**全部別物**でした。
🔴 **1回目で「Apple GPU では無理」と結論していたら、5.9倍の高速化を捨てていました。**

### 10-3. 「繋がらない」を見たら、まず相手が居ることを確かめる

サーバが起動していないのに接続テストをして、「この環境はブロックされている」と誤って結論しました。
**居ないものに繋がらないのは当然**で、それを環境の制約と読むと、**存在しない壁を記録に残す**ことになります。
→ `lsof -nP -iTCP -sTCP:LISTEN` で**相手が待ち受けているか**を先に見てください。

### 10-4. 自分で計算せず、その仕事を知っている層に渡す

同じ形の失敗を3回しました。

| やったこと | 起きたこと | 正解 |
|---|---|---|
| ffmpeg で文字を描こうとした | その機能が無かった | **ブラウザ（CSS）に描かせる** |
| 字幕を自分で19文字ごとに折った | 語の途中で切れ、行ごとに幅がガタついた | **CSS の折り返しに任せる** |
| 要素の位置を「文字サイズ×1.45」で計算した | **見出しが2行になった瞬間に重なった** | **flex で縦積みさせる** |

🔴 **文字数は台本次第で変わるので、レンダ前に高さは決まりません。** 計算しようとすること自体が誤りです。

### 10-4b. 🔴 再現しない原因が「乱数」とは限らない

**Python 組み込みの `hash()` は、文字列に対してプロセスごとに違う値を返します**（`PYTHONHASHSEED`）。
乱数を1行も使っていないのに**焼くたびに結果が変わる**という、いちばん原因を追いにくい形になります。
→ 振り分けやキャッシュのキーに使うハッシュは **`hashlib`** にしてください。

⚠️ **独立したハッシュで見た目を振り分けると「たまたま3段続けて同じ背景」が普通に起きます。**
プールの長さと**互いに素**な数だけ回す方式にすれば、隣が必ず異なることを**構造で保証**できます。

### 10-5. 長時間の処理は、切り離して実行する

10分を超える処理をバックグラウンドに投げると、途中で止められることがあります。

```bash
cat > run.sh <<'EOF'
#!/bin/bash
cd /path/to/project
python3 -u tools/heavy.py > logs/heavy.log 2>&1
echo "EXIT=$?" > logs/heavy.exit      # ← 完了の目印をファイルに残す
EOF
chmod +x run.sh && nohup ./run.sh > /dev/null 2>&1 & disown
```

- **`-u`（バッファなし）を付ける。** 付けないと途中で止まったときログが**0バイト**になります
- **完了判定はプロセスの生死ではなくファイルの出現で行う**

### 10-6. 「口が動いているか」の検査は測り方を間違えやすい

- **顔全体の画素差で測らない。** 口しか動かない方式では差が出ず、**正常なのに「静止」と誤判定**します
- **無音区間を除外する。** 文の切れ目で口を閉じているのは**正しい挙動**です
- **方式ごとに閾値を持つ。** ある方式用に決めた閾値を、動き方の違う方式にそのまま当てないでください

### 10-7. 却下の記録には「その理由が効く条件」を書く

「SadTalker は遅いので不採用」とだけ残すと、条件が変わっても引き継がれます。
実際には「**10分の動画では**不採用」でした。尺が1分なら成立します。

```
× SadTalker は遅いので使わない
⭕ SadTalker は実時間の183倍。10分動画=30時間なので この用途では使わない（尺が短ければ成立しうる）
```

**倍率のような線形に効く数字は、条件を変えたときの再計算に使える資産**になります。

### 10-8. 短い尺で測って外挿してよい（一度だけ確かめる）

10秒で測った倍率（17.8倍）から60秒を予測したところ、実測 17.0倍でほぼ一致しました。
**外挿が使えると一度確かめておくと、その後の検証コストが17分から3分に下がります。**

## 13. 付録：良い資料にするための書き方

技術が動いても、**画面に出す情報が薄いと動画は良くなりません**（実例: 10点満点で2点相当の評価）。

| やりがちなこと | 直し方 |
|---|---|
| 1つの文を2つに割って箇条書きにする | **要素を並べる**（担当プロダクト2つ、質問例2つ、など） |
| 「明日は」のような**続きが無いと意味をなさない見出し** | 見出し単体で意味が通る言葉にする |
| 素材にある具体を要約して捨てる | **固有名詞と数字をそのまま出す**（「◯◯（製品名）」「毎朝レポートを自動で届ける」のように、素材に書かれた言葉をそのまま使う） |
| 全部を字幕で流す | 字幕は**読ませたい時だけ**。声で伝わることを文字で繰り返さない |

🔴 **資料が一般論になるのは、たいてい素材不足ではなく、素材の具体を捨てたからです。**

# Ａヨミ案件 自動転記（ヨミ表 → Ａヨミ案件）

ヨミ表（スプレッドシート1）のステータスが **Aヨミ** または **受注** になったら、
Ａヨミ案件（スプレッドシート2）へ自動で行を転記・更新する Google Apps Script。

- 転記元：[スプレッドシート1](https://docs.google.com/spreadsheets/d/1t7pVp895kKB0vWWHbq-h_hfDAp0HkW5oc1cW20HeCtQ/edit?gid=608567082) シート「ヨミ表」
- 転記先：[スプレッドシート2](https://docs.google.com/spreadsheets/d/1svI03RoBoqNtrhpWBSCJ8_W4uaPQBcRvEfIpw9D_hH0/edit?gid=470357897) シート「Ａヨミ案件」
- 同期方向：**ヨミ表 → Ａヨミ案件 の一方向のみ**

## 動きかた

```
ヨミ表 P列（ステータス）が Aヨミ / 受注 になる
   │
   ├─ 初回商談日（R列）が 2026/07/20 以降？ ── いいえ → 何もしない
   │      はい
   ├─ BB列「Aヨミリスト転記」に転記ナンバーがある？
   │      ある → Ａヨミ案件の同じナンバーの行を上書き更新
   │      ない → 会社名＋担当名（姓）でＡヨミ案件を検索
   │                見つかった → その行に紐づけて更新（重複させない）
   │                無い       → 最終行に新規追加
   │
   └─ ヨミ表・Ａヨミ案件の両方のBB列に同じ転記ナンバー（A-0001 …）を書き込む
```

一度転記された行は、その後ステータスが **失注・リスケ等に変わっても行は消さず、
Ａヨミ案件のステータスだけを追随して書き換える**。

発火は2系統：

| | 内容 |
|---|---|
| 編集時トリガー | ヨミ表の P列 / R列 / BB列 が編集された瞬間に、その行だけ同期 |
| 時間主導トリガー | 1時間ごとに全行をチェック（貼り付け・一括更新の取りこぼし対策） |

## 列の対応

B〜Q列は両シートで並びが同じなので 1:1 で転記。**R列以降は並びが違う**ため個別に対応させている。

| ヨミ表（スプシ1） | | Ａヨミ案件（スプシ2） |
|---|---|---|
| B〜Q（会社名〜セミ参加日） | → | B〜Q（同じ並び） |
| U 受注日 | → | R 受注日 |
| R 初回商談日 | → | S 初回商談日 |
| S 2回目商談日 | → | T 2回目商談日 |
| W 受注商品数 | → | AB 受注商品数 |
| X 提案商品/受注商品 | → | AC 商品 |

**同期しない列**（ヨミ表に対応する列が無い／単位が違うため、スクリプトは一切触らない）

- Ａヨミ案件の `U` / `V 回収予定日` / `W メモ` / `X 初期費用` / `Y 月額費用` / `Z 期間` / `AA 合計金額`
- Ａヨミ案件の `A 担当営業` — 両シートで表記が違い（フルネーム／苗字のみ）プルダウンに弾かれるため。**手入力で運用する**
- → Ａヨミ案件側で手入力した内容は、上書き更新でも消えない

A列も同期させたくなったら、`CONFIG.SYNC_MAP` の先頭に `{ src: 1, dst: 1 },` を足す。

ヨミ表 `V 受注金額・提案金額（万円）` と Ａヨミ案件 `AA 合計金額（円）` は単位が違うので同期対象外にしている。
連動させたい場合は `CONFIG.SYNC_MAP` に追加する（換算が必要）。

## ステータス

**Ａヨミ案件のP列は `受注` / `Aヨミ` / `失注` の3つにしかならない。**
ヨミ表の細かい表記（`（決裁者口頭合意済）` など）はそのまま持ち込まず、書き込む前に丸める。

| ヨミ表の値 | Ａヨミ案件に書く値 | 未転記の行を転記するか |
|---|---|---|
| `Aヨミ（決裁者口頭合意済）` / `Aヨミ（決裁者確認中）` / `Ａヨミ` | `Aヨミ` | する |
| `受注` | `受注` | する |
| `Cヨミ（長期）` / `リスケ` / `追客NG` / `受注後キャンセル` / `失注` など上記以外 | `失注` | しない |
| 空欄 | 空欄のまま | しない |

判定は全角・半角・空白の揺れを吸収してから行う。丸め方は `CONFIG.STATUS_MAP` で変えられる。

`setupStatusDropdown()` を実行すると、Ａヨミ案件のP列のプルダウン自体もこの3択に張り替わる
（手入力でも他の値を選べなくなる）。

### プルダウンに無い値は書き込まない

Ａヨミ案件の列にはデータの入力規則が設定されている。候補に無い値を書こうとすると
Apps Script は例外を投げるので、**弾かれるセルだけ外して、残りの列は書き込む**。
弾かれたセルは `_同期ログ` に「スキップ」として、値と候補つきで記録される。

```
スキップ | 株式会社◯◯ | Ａヨミ案件 A33 は入力規則にない値なので書き込まなかった：
                        「土屋慧介」（候補： 土屋 / 村田 / 敬彦 / 榎本 / 鈴木）
```

これが出たら、ヨミ表側の表記を候補に合わせるか、Ａヨミ案件の入力規則に値を足す。
（担当営業のA列は、この理由で同期対象から外してある）

## 重複防止

`BB列（Aヨミリスト転記）` の**転記ナンバー**が正。番号が入っていればそれで突合する。

番号が無い行は **会社名＋担当名（姓）** で照合する。照合時は法人格（株式会社・㈱など）、
空白、記号、全角半角を落として比較するので、`株式会社ベータ` と `ベータ株式会社` は同じ案件として扱う。

`BB列` に `対象外` と入っている行は同期しない。**転記したくなったらBB列を空にすれば**、
次の同期で通常どおり転記される。

姓の入れ方が違う（片方が `横田`、片方が `横田徳`）と会社名が同じでも一致せず `対象外` になる。
その取りこぼしは `relinkExcludedByCompany()` を実行すると、**会社名だけで**突合し直して紐づけられる。

## 導入手順

1. スプレッドシート1を開く →「拡張機能」→「Apps Script」
2. `Code.gs` の中身を貼り付けて保存
3. 関数 `setupStatusDropdown` を実行（初回の権限承認が出るので許可）
   - Ａヨミ案件のP列を `受注 / Aヨミ / 失注` の3択に固定する
4. 関数 `initialLinkExisting` を実行
   - いま既にAヨミ／受注になっている行を整理する。Ａヨミ案件に同じ案件があれば紐づけるだけ、無ければ `対象外` を入れて一括流し込みを防ぐ
5. 関数 `relinkExcludedByCompany` を実行（任意）
   - 姓の表記違いで `対象外` になった行を、会社名だけで突合し直す
6. 関数 `setupTriggers` を実行
   - 編集時トリガーと1時間ごとのトリガーが設置される

> トリガーは実行した人のアカウント権限で動くため、**スプレッドシート2への編集権限がある人**が実行すること。

## ログ

スプレッドシート1に `_同期ログ`（非表示シート）が自動生成され、
`日時 / 種別 / 転記No / 会社名 / ステータス / 詳細` が記録される。5000行を超えると古い行から消える。

種別は `新規` `更新` `紐づけ更新` `再作成` `リンク` `対象外` `見送り` `スキップ` `エラー`。

- `見送り` … Aヨミ／受注になっているが初回商談日が対象期間外・未入力で転記しなかった
- `スキップ` … 転記先の入力規則に無い値だったので、そのセルだけ書き込まなかった

**転記されなかった理由**はこの2つで分かる。

## 設定の変更

`Code.gs` 冒頭の `CONFIG` で変えられる。

| 項目 | 内容 |
|---|---|
| `TARGET_FROM` | 対象にする初回商談日の下限（現在 2026/07/20） |
| `DST_STATUS_VALUES` | Ａヨミ案件のP列に許す値（現在 受注 / Aヨミ / 失注） |
| `STATUS_MAP` | ヨミ表のステータスをどの値に丸めるか |
| `SYNC_MAP` | 列の対応表 |
| `SRC` / `DST` の `COL_*` | 各シートの列番号（列を挿入したらここを直す） |
| `LOG_MAX_ROWS` | ログの保持行数 |

見出し行はP列が「ステータス」になっている行を先頭5行から自動判定するので、
上に行を差し込んでも動く。ただし**列の挿入・削除をすると対応がズレる**ので、`CONFIG` の更新が必要。

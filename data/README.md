# hiroshi-sent-log.csv — ヒロシ商談フォローの送信台帳

## これは何か

商談後フォローメール（AIアシスタント「ヒロシ」名義）を **誰にいつ送ったか** の唯一の正本。
重複送信を防ぐための除外判定は、このファイルだけを見て行う。

## なぜスプレッドシートではないのか

Google スプレッドシートの「送信mailログ」タブは人が見るには良いが、
現在の Claude Code 環境には **セル書き込みのツールが無い**（Drive MCP の `update_file` は
タイトルと保存先しか変更できない）。そのため送信結果をシートへ自動反映できず、
「実際は送ったのにシート上は未送信」というズレが起きて二重送信の原因になった（2026/09/01）。

Git リポジトリなら Bash で確実に読み書きでき、コミットで履歴も残るため、こちらを正本とする。
スプレッドシートは人間向けの閲覧用ミラーという位置づけ。

## 列

| 列 | 内容 |
|---|---|
| 送信日 | YYYY-MM-DD |
| 会社名 | ヨミ表の会社名と一致させる |
| 送信先 | 実際に送ったアドレス |
| 件名 | 実際に送った件名（再送時に同じ切り口を繰り返さないための参照用） |
| 状態 | `送信済み` / `バウンス` / `保留` |
| 備考 | 自由記述 |

## 除外ルール

- 状態が `送信済み` で、送信日から **30日以内** の会社は次回の対象に含めない。
- 状態が `バウンス` の会社は、正しいアドレスが判明するまで対象に含めない。
  **アドレスを推測して送らないこと**（他人に商談内容が届く事故になる）。

## 使い方（バッチから）

直近30日以内に送信済みの会社名を得るには、`送信日` と `状態` で絞り込む。
Python の `csv.DictReader` で読み、`状態 == '送信済み'` かつ
`送信日 > 今日-30日` の行の `会社名` を集めれば除外リストになる。

追記は同じ形式で行を足し、
`git commit && git push -u origin claude/deal-followup-ai-strategy-dxvom8` すること。
コミットしないとコンテナ再作成時に消える。

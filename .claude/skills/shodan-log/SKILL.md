# 商談ログ処理

担当者が貼り付けたログ **だけ** を処理する。自動録音・自動文字起こしを勝手に開始しない。

## 0. 前提の読み込み

処理前に必ず Drive の正本を読む。

- 共通設定 `1R206xidfxLmJRVkbUIIyI_Q0JmEaNY8hr0lGydbpCWg`
- 担当者設定 `1NrCij2HX9PvgQ5fmVODVM7juDHhKMOi1z0ussj8MWao`

読めない場合はリポジトリの `CLAUDE.md` を使い、報告に「正本を読めなかった」と明記する。

## 1. 重複チェック（最初にやる）

`99_処理台帳`（`1IH8Ps9K9fCjPEnchDzaeMAgpEtuOnavu`）を検索。

```
parentId = '1IH8Ps9K9fCjPEnchDzaeMAgpEtuOnavu' and title contains 'YYYY-MM-DD__商談ログ__<企業名>'
```

「完了」ファイルがあれば、作り直さず担当者に「すでに処理済みです」とだけ伝える。

## 2. 抽出

1. 企業名、参加者、日時、商談目的を特定する
2. 顧客課題、要望、発言内容を整理する
3. **確定事項** と **AIによる提案・仮説** を分ける（仮説には「仮説」と明記）
4. 決定事項、未決事項、要確認事項を整理する
5. 次に確認すべき質問を抽出する

企業名や参加者を一意に特定できなくても **作業を止めない**。
作れる文書は作り、不明箇所を「要確認」とする。

## 3. 過去事例の検索

`04_営業ナレッジ` と `03_議事録`、および Drive 内の提案資料から関連事例を検索する。
情報源の優先順位は共通設定 7 に従う。矛盾は統合せず「要確認」として両論併記する。

## 4. 作成物

| # | 作成物 | 保存先 |
|---|---|---|
| 1 | 顧客向け議事録 | `03_議事録` / `議事録_顧客向け_YYYY-MM-DD_企業名` |
| 2 | 社内向け詳細記録 | `03_議事録` / `議事録_社内向け_YYYY-MM-DD_企業名` |
| 3 | 顧客向けフォローメール | Gmail 下書き |
| 4 | 社内確認依頼文 | Gmail 下書き（社内確認先ごと） |
| 5 | 紹介メール | Gmail 下書き（候補がある場合） |
| 6 | 営業ナレッジ | `04_営業ナレッジ` |

**顧客向け議事録と社内向け詳細記録は必ず別ファイルにする。**

顧客向け文書に含めてはいけないもの: 他社名 / 他社の金額・契約条件 /
他社の未公開情報 / 社内だけの評価・懸念 / 個人情報 / 顧客に開示していない仮説

## 5. 紹介候補

相手の商材を求めている可能性がある過去の取引先を **3社以内** で抽出。
各候補に 候補理由 / 最終接触日 / 情報鮮度 / 注意点 を必ず付ける。
除外顧客・連絡禁止先は候補から外す。他の営業担当者の顧客は、
社内ルールまたは明示的な許可が確認できる場合のみ。

## 6. 宛先が確定できない場合

**Gmail 下書きの保存だけを保留する。** 他の文書作成は続行する。
担当者を責めず、励ましながら分かりやすく宛先を確認する。

## 7. ToDo 整理

自社側・顧客側それぞれの ToDo、担当者、期限を表にする。

## 8. 読み直し確認

作成したファイル・下書きを **すべて再取得** し、保存先・宛先・件名・本文を確認する。

## 9. 台帳へ記録

`99_処理台帳` に `YYYY-MM-DD__商談ログ__<企業名>__完了` を作成。
実行日時・実行環境・処理対象・作成物・参照情報・要確認事項・成功/失敗を記録する。
**商談ログ全文は複製しない。**

## 10. 報告フォーマット

```
# 商談レポート

## 3行まとめ

## ✅ 決まったこと

## 🟡 確認が必要なこと

## 📋 次のアクション
| ToDo | 担当 | 期限 | 状態 |

## 💡 関連事例
| 事例 | 類似点 | 今回への活用方法 | 情報源 |

## 🤝 紹介候補
| 候補企業 | 候補理由 | 情報鮮度 | 注意点 |

## 📝 作成したもの

## ✅ 担当者が行うこと
```

送信はしない。すべて下書きまで。承認待ちを「送信済み」と書かない。

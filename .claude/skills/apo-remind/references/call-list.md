# 架電リストの出力書式

前日リマインドの成果物。**これを見た営業が、そのまま受話器を取れる状態**にすることが目的。
「誰が・何時に・どこへ・何を言うか」が1画面で完結していること。

## 書式

```markdown
# 前日リマインド｜8/4（火）分

対象日 2026-08-04（火）｜全アポ 24件 ｜ 下書き作成 20件 ｜ 要架電 5件 ｜ 手動対応 4件

---

## ⚠ 手動対応が必要（4件）

カレンダーに顧客情報が入っていないため、リマインドを自動生成できませんでした。

| 時刻 | 担当 | 予定名 | 対応 |
|---|---|---|---|
| 11:00 | 榎本 | 株式会社塗王.com 松本様 | 連絡先を確認して手動で連絡 |
| ... |

> 予定を手動で作成する際、description に次の3行を入れておくと翌日から自動化に乗ります。
> `ゲスト会社名 : ` / `ゲスト氏名 : ` / `ゲストメールアドレス : `
```

## 書き方のルール

- **「ひとこと」欄には description から取れた事実だけを書く。** 業種・課題・顧客コメント・紹介コード・お電話口担当が材料。**推測で温度感や提案内容を書かない。**
- 電話番号は携帯（080/090始まり）を優先。複数あれば1つ目に携帯、括弧書きで固定を添える。
- 架電理由は判定条件をそのまま書く（「メールアドレスなし」「朝イチ枠」「【来社】」など）。なぜ電話するのかが分かれば、営業側で取捨選択できる。
- P1が6件を超えたら、リストの末尾に次の1行を添える：
  > 要架電が{N}件に増えています。`config/team.json` の `callPriority` を見直してください。
- 該当0件のセクションは「該当なし」と1行で書き、表は出さない。

# カレンダーイベント → 顧客アポ情報 の抽出仕様

実データ（2026-08-04、第一営業部6名）で検証済みのルール。

## 1. 顧客アポかどうかの判定

**顧客アポと判定する条件（いずれか）**

- `description` に `ゲスト会社名` / `ゲスト氏名` / `ゲストメールアドレス` のいずれかの行がある（TimeRex経由の予定。全体の8割強がこれ）
- `summary` が `{会社名} {氏名}さん: {商談名}` の形式になっている
- `summary` に `株式会社` / `有限会社` / `合同会社` / `合資会社` / `様` / `さん` を含み、かつ後述の除外条件に当たらない

**除外する条件（`config/team.json` の `exclude`）**

- `titleContains` のいずれかを含む → 社内予定
- `titleExact` に完全一致する → 社内予定
- attendees が `@writeup.co.jp` と会議室リソース（`@resource.calendar.google.com`）だけ、かつ description に顧客情報行が一切ない → 社内MTG
- `status: "cancelled"`
- TimeRexの `確保時間` イベント（前後バッファ。description が `日時:／予定名:／ゲスト氏名:` の3行だけ）

判定に迷った予定は**除外せず「手動対応」に回す**。メールを作らないのは安全側だが、アポを丸ごと落とすのは危険なため。

## 2. description のパース

TimeRexが出力する `ラベル : 値` 形式。**ラベル名に揺れがあるので、以下をすべて同義として扱う。**

| 取りたい情報 | 実際に現れるラベル |
|---|---|
| 会社名 | `ゲスト会社名` |
| 氏名 | `ゲスト氏名` |
| メール | `ゲストメールアドレス` |
| 電話番号 | `緊急連絡先（携帯番号）` / `電話番号（ハイフンあり）` / `電話番号` |
| 従業員規模 | `従業員規模` |
| 業種 | `業種` |
| 課題 | `お忙しい業務/AI化したい業務` |
| 顧客コメント | `ゲストコメント` / `ご相談内容` |
| 紹介コード | `紹介コード` |
| アポインターの担当 | `お電話口担当` |
| Web会議URL | `Web会議室` の行、または `conferenceUrl` / `location` |

パース時の注意：

- **HTMLが混ざる。** `<a href="mailto:xxx@yyy.jp">xxx@yyy.jp</a>` や `<a href="https://www.google.com/url?q=https://meet.google.com/...">` の形で入る。タグを剥がし、Googleのリダイレクト（`https://www.google.com/url?q=` プレフィックス）を外して素のURL/アドレスを取る。
- **電話番号が複数入ることがある。** 例：`050-7572-2890,090-3376-8081` → カンマ区切りで両方保持し、架電リストには携帯（080/090始まり）を優先して先頭に出す。
- **ラベルはあるが値が空**のことが多い（`業種 : ` など）。空は「不明」として扱い、創作しない。
- 会社名が空で氏名だけ、というケースがある（個人事業主）。その場合は氏名を会社名欄に流用せず、会社名は空のまま扱う。

Web会議URLは `description` の `Web会議室` 行より、イベントの `conferenceUrl` フィールドを優先する（HTMLエスケープが無く確実なため）。

## 3. 担当営業の決定と重複排除

同じアポが複数メンバーのカレンダーに現れる。`event.id` をキーに統合する。

- **担当営業 = `organizer.email` が `members[]` にあるメンバー。**
- organizer が `members[]` に無い場合（例：`@events.timerex.net`、他部署が主催）→ そのイベントを持っていたカレンダーの持ち主を担当とする。複数いれば `attendees` で `responseStatus: "accepted"` のメンバーを優先。
- 統合したイベントに他のメンバーも入っていれば「同席：〇〇」として保持し、架電リストに表示する（誰が電話するかを迷わせないため、**架電担当は1人に確定させる**）。

同一 `event.id` でも、繰り返し予定は `id` に `_YYYYMMDDTHHMMSSZ` が付いて日付ごとに一意になるので、そのまま比較してよい。

## 4. 商談種別の判定（メールテンプレートの選択に使う）

| 種別 | 判定 |
|---|---|
| `初回オンライン` | `summary` に `AI化スタート診断` を含み、`2回目`/`3回目`/`訪問`/`来社` を含まない |
| `2回目以降` | `summary` に `2回目` / `3回目` / `（2回目` などを含む |
| `来社・訪問` | `summary` に `【来社】` / `訪問` を含む、または `location` が会議室リソース名で `conferenceUrl` が無い |
| `既存顧客MTG` | `summary` に `キックオフ` / `オンボーディング` / `納品` / `Lシンク` / `CMS` / `MEO` を含む |
| `その他` | 上記以外 |

判定できない場合は `その他` とし、汎用テンプレートを使う。

# 入力事故の実例と、AIOマスターのbotの挙動

実際のオンボーディング画面（飲食店「東京橋」の例）で起きた事故。botは入力チェックが弱く、
おかしい値でもそのまま通して確認画面まで進み、「設定して始める」が押せてしまう。
このスキルの出力は、これらを起こさない形になっている。

## 起きた事故

| 欄 | 入力された値 | 何が起きたか |
|---|---|---|
| サービス名 | 店舗説明文をそのまま貼る → 「貸切店舗予約 テレビ撮影 ドラマ撮影 イベントスペース 店舗貸切」（スペース区切り） | 「10件になっています」「30文字以内で」と弾かれ、最終的に1件だけになった |
| 地域 | `https://tsuku2.jp/sushibar` | 「https:」「tsuku2.jp」「sushibar」の3エリアとして登録され、地域質問が全滅 |
| 競合企業 | `わかりません` | 「わかりません」という会社が1社として記録された |
| 顧客の課題 | `わかりました` | 課題が空のまま。課題起点の質問が作れない |
| ご指定の質問 | 単語をスペースで並べたもの | 質問文ではないため、長い1問として扱われた可能性 |
| サイトURL | `https://tsuku2.jp/`（プラットフォームのトップ） | 自社ページではないので、FAQ・llms.txt実施の毎朝チェックが機能しない |

結果、生成された質問が「東京京橋でおすすめの**飲食店会社**は？」のような、誰もAIに聞かない言い回しになった。

## botの挙動（仕様として覚えておく）

- ヒアリング順：サービス名 → サイトURL → 地域 → 競合企業 → 顧客の課題 → サービス・強み → ご指定の質問 → 確認画面
- サービス名は「○○に強い会社は？」の○○にそのまま入る
- 地域は「○○で△△に強い会社は？」の○○に入り、地域ごとに質問が作り分けられる
- 50問は「5カテゴリ×各10問」で自動生成（おすすめ系・地域系・課題起点・比較系・指定質問）
- 判定基準：週3回・月12回の計測のうち、月内2回以上掲載された質問のみ「掲載」
- 料金：月額固定0円＋掲載維持1問×1万円（上限3万円/月）。**掲載された質問数で課金**されるため、
  社名入り質問など「出て当然で客が来ない」質問が50問に混ざると費用だけ増える

## 事故を防ぐ出力上の工夫

- 各欄をコードブロックで分け、区切り文字（読点／改行）を欄ごとに正しく使う
- 競合・課題は必ず中身を入れる。分からなければ Step 2 の検索で埋める
- 地域は所在地ではなく「お客様が探す場所」。URLは絶対に入れない
- 指定質問は「〜は？」「〜を教えて」「〜どこ？」で終わる話しかけ文にする
- 末尾に「貼り付け前の注意」と「設定直後にやること」を必ず付ける

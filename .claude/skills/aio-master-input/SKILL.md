# AIOマスター 入力例生成スキル

## このスキルの目的

AIOマスターは「AIに○○を聞いたとき、御社が回答に出てくるか」を週3回計測し、掲載された質問数で課金するツール。
計測の精度は、オンボーディングで入力する7項目の質でほぼ決まる。
営業マンや顧客が自力で入力すると、地域欄にURLを入れる・競合欄に「わかりません」と書く・質問文ではなく単語を並べる、といった事故が頻発し、
掲載率0%のまま改善指示書も役に立たない状態になる（実例は `references/pitfalls.md`）。

このスキルは、企業URLから **そのまま各欄に貼れる7項目** を作り、入力事故を根絶する。

## 設計原則（なぜその書き方にするか）

AIが回答で会社名を挙げるとき、引用するのは「具体的で他社と違う事実」であって感情やスローガンではない。
だから各欄は次の考え方で書く。

| 欄 | 考え方 |
|---|---|
| サービス名 | 社内の呼び名ではなく **お客様がAIに聞くときの一般名**。ツールはこれを「○○に強い会社は？」にはめ込む |
| 地域 | 会社の所在地ではなく **お客様が探す場所**。ロケ弁なら撮影地、店舗なら最寄り駅 |
| 競合企業 | 推測で書かない。**AIに実際に聞いて出てくる会社名** を入れる。ここが違うと「AIが御社の代わりに挙げた会社」の計測が無意味になる |
| 顧客の課題 | 「担当者の困った」を具体的に。失敗できない理由、探しても見つからない理由 |
| サービス・強み | 事実 ＋ その事実が誰を守るか。数字（時刻・台数・食数・社数）が入るほどAIは引用する |
| ご指定の質問 | 検索窓の単語ではなく **AIへの話しかけ文**。1行1問 |

未確認の数字は創作しない。「○」のプレースホルダで渡し、確認シートで埋めてもらう。

## 実行手順

### Step 1：企業情報を集める

1. URLを WebFetch で取得。トップで足りなければ 会社概要／事業内容／サービス ページを1〜3枚追加取得
2. 取得できない（EGRESS_BLOCKED 等）場合は WebSearch で `"会社名" 株式会社`、`site:ドメイン`、`会社名 事業内容` を検索し、
   会社情報サイト・プレスリリース・求人票から拾う。プレスリリースは数字（取引社数・年間食数・配送エリア）の宝庫
3. 集めるもの：社名／所在地／事業一覧／対象顧客／強み／実績の数字／拠点／対応エリア
4. **確認できた事実と、確認できなかった事実を分けて持っておく**。強み欄には確認済みの事実だけを書き、未確認は確認シートに回す

### Step 2：競合をAIの回答から取る

サービス名と地域を組み合わせて WebSearch する（例：`東京 ロケ弁 おすすめ 業者`、`飲食店 仕込み代行 東京`）。
検索結果・記事で実名が挙がる会社を3〜5社選ぶ。事業が複数ある会社は、主軸の事業から3社、副次の事業から1〜2社。
大手プラットフォーム（ごちクル等）が実際に挙がるなら入れてよいが、挙がらないのに入れない。

### Step 3：7項目を書く

`references/output-template.md` の書式で出力する。各欄の仕様（区切り文字・件数・文字数）は同ファイルに書いてあるので必ず守る。

書くときの具体ルール：
- サービス名は **主軸→副次** の順。計測対象（契約時に確定、画面から変更不可）が分かっていればその事業を先頭に
- 指定質問10問は、主軸事業6〜7問・副次事業3〜4問。地域違い・人数違い・急ぎ・時間厳守など **お客様の状況の違い** で散らす
- 強み欄は、確認済み事実で文を作り、数字が未確認の箇所は「○」にして文は残す。削除候補の文（対応の有無が不明なもの）は確認シートで「無なら削除」と指示する
- 営業マンの提案資料やSNS企画（「早朝の仕込み」「時間厳守の裏側」等）を渡された場合は、感情ではなく **その根拠になっている事実** を抜き出して強み欄・課題欄・質問に織り込む

### Step 4：注意書きと設定後チェックを付ける

出力の末尾に `references/output-template.md` の「貼り付け前の注意」「設定直後にやること」をそのまま付ける。
特に「社名入りの質問が自動生成50問に混ざっていないか」は重要。
このツールは掲載された質問ごとに課金されるため、社名入り質問は **掲載されて当然なのに客は来ない** 質問で、費用だけ増える。

## 出力の形

必ず `references/output-template.md` の構成で出す。順序は①〜⑦ → 確認シート → 貼り付け前の注意 → 設定直後にやること。
各欄はコードブロックで囲み、ユーザーがそのままコピーできるようにする。欄の外に説明を長く書かない。

完成例（ロケ弁・仕込み代行のCOH社）は `references/example-coh.md`。
業種が違っても「欄ごとの考え方」と「確認シートの作り方」はこの例に倣う。

## よくあるケース

- **会社名だけ渡された**：WebSearch で公式サイトを特定してから Step 1 へ
- **店舗（飲食店・サロン等）**：地域は「駅名・エリア名」、サービス名は「貸切」「宴会」「個室」など利用シーンの一般名。競合は同エリアの同業態
- **BtoBサービス業**：地域は「国内」「日本」で1件にし、残りは主要都市。質問は「○○を外注できる会社」「○○に対応してくれる業者」型
- **情報が極端に少ない会社**：分かる範囲で7項目を作り、強み欄は「○」だらけでも文の骨格を渡す。空欄より埋めやすい

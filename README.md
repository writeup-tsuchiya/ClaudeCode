# 前日リマインド自動化（第一営業部）

オンライン商談アポの**前日リマインド電話**を自動化する仕組み。

## 解こうとしている問題

| | Before | After |
|---|---|---|
| 対象 | 1日 約15件のアポ | 同じ |
| 手段 | 全件に人が電話 | メール全件自動 ＋ 電話は絞った3〜5件 |
| 工数 | **約2時間/日** | **約30分/日**（メール確認10分＋架電20分） |

電話を全廃するのではなく、**電話が効く先だけ電話に残す**ハイブリッド構成。
朝イチ枠・来社/訪問・重要案件・連絡先がメールしか無い先は、抑止力が落ちるので人が架けます。

## 仕組み

```
毎日 17:00 (JST)
   │
   ├─ 第一営業部6名のGoogleカレンダーから翌営業日の予定を取得
   │     urashima / k_tsuchiya / t_kanno / murata / k_yoshikawa / enomoto
   │
   ├─ 社内MTGを除外し、顧客アポだけを抽出（TimeRexのdescriptionをパース）
   │     会社名・氏名・メール・電話・業種・課題・Meet URL
   │     同席案件は event.id で重複排除し、担当を1人に確定
   │
   ├─ 架電優先度を判定
   │     P1（人が架電）… メール無し / 11時前開始 / 来社・訪問・★・キックオフ・納品・2回目以降
   │     P2（メールのみ）… それ以外
   │
   ├─ メールアドレスが取れた全件について Gmail下書きを作成
   │     To=顧客、Cc=担当営業、文面は商談種別ごとのテンプレート
   │
   └─ 架電リストを出力（担当ごと・電話番号・架電理由・話の材料つき）
```

## 構成

```
config/team.json                              設定。対象メンバー・架電条件・自動送信フラグ
.claude/skills/apo-remind/
    SKILL.md                                  実行手順の本体
    references/extraction.md                  カレンダー → 顧客情報 の抽出仕様
    references/mail-templates.md              メール文面テンプレート（種別A〜E）
    references/call-list.md                   架電リストの出力書式
docs/runbook.md                               日次運用・切替手順・トラブルシュート
```

## 使い方

**手動実行**（任意の日を対象にできる）

```
明日のリマインドやって
8/10のリマインドリスト作って
```

`apo-remind` スキルが起動し、下書き作成と架電リスト出力まで走ります。

**自動実行**

毎日 17:00 (JST) の Routine から起動します。日〜木に発火し、翌営業日を対象にします。
設定・停止方法は `docs/runbook.md` を参照。

## いまの制約（重要）

- **Gmail下書きは `aizawa@writeup.co.jp` にしか作れません。** Gmail APIは認証済みアカウントにしか書き込めないためです。
  現状は「1アカウントから送信・Ccに担当営業・署名は担当営業名」で運用します。
  各営業が自分のアドレスから送りたい場合の対応は `docs/runbook.md` の「送信元アカウントの本番構成」を参照。
- 営業が手動でカレンダーに入れた予定（TimeRex経由でない予定）は顧客情報が無いため自動化に乗りません。
  8/4のデータでは24件中4件が該当。**手動作成時に `ゲスト会社名 : ` `ゲスト氏名 : ` `ゲストメールアドレス : ` の3行を書く運用**にすれば解消します。
- まずは `delivery.autoSend: false`（下書きまで）で運用してください。2週間ほど内容を確認し、問題なければ `true` に変えると送信まで自動になります。

## 電話をAI音声で自動化したい場合

今回はメール＋人の架電のハイブリッドで組んでいますが、電話そのものを自動化する余地は残しています。
架電リスト（P1）がそのまま発信対象リストになるので、IVRy / Twilio 等の音声AIに渡す形で拡張できます。
検討する場合の論点は `docs/runbook.md` の「AI音声架電への拡張」に整理しています。

# Google Meet 商談ログの自動集約

第一営業部7名がGoogle Meetで商談した際、Gemini in Meetが自動生成する「Gemini によるメモ」（メモ＋文字起こし）を、
土屋所有の集約フォルダ「Google Meet」内のGoogleドキュメント `商談文字起こし集約（全期間）_N` に**連結して蓄積する**仕組み。
下流の「ヒロシ商談フォロー」バッチがこのドキュメントを全文検索して商談ログURLを引いている。

運用手順・障害対応・管理者向け設定は **`docs/meet-archive-ops.md`** にまとめている。本節は概要のみ。

## 解こうとしている問題

Gemini in Meetのメモ／文字起こしは、デフォルトでは**商談した本人のDriveにしか残らない**。
他の営業マンや管理者が横断的に事例を探したり、AIが過去商談を参照したりできない。

## 仕組み（2026-10-25 改訂）

```
毎日 7:30 (JST)  Routine「Google Meet 商談アーカイブ（日次追記）」
   │
   ├─ 1. 7名のGoogleカレンダーから直近3日の予定を取得し、
   │      「Gemini によるメモ」が添付された予定だけを候補にする（カレンダー起点）
   │      社内MTG（config/team.json の exclude.*）は除外
   │
   ├─ 2. scripts/meet_archive/archive.py が候補を読み、
   │      manifest 未登録分だけを「商談文字起こし集約（全期間）_N」に連結して書き込む
   │      読めなかった商談（ボットに未共有）は manifest.lastRun.unreadable に記録
   │
   └─ 3. manifest を commit & push し、Slack に「取り込み／読めず」を毎日報告する
```

### なぜ「カレンダー起点」か

当初は各メンバーのDriveフォルダ（Meet Recordings）を見張っていた。しかし2026-09以降、Gemini in Meetが保存先を
「Google Meet/<商談名>/」に変え、さらに「Google Meet」フォルダ自体を作り直すようになった。共有してもらったフォルダに
新しいメモが入らなくなり、ボットから見えない＝「新規0件・正常終了」が約1.5か月続いた（詳細は docs/meet-archive-ops.md 1章）。
カレンダーの予定にはメモがファイルIDつきで添付されるので、**フォルダ構造に依存せず全商談を発見できる**。

### 読み取り権限

発見できても、ファイルがボットに共有されていなければ読めない。読めなかった分は毎日Slackに出し、該当メンバーに共有を依頼する（応急処置）。
恒久策は Workspace 管理者による**ドメイン全体の委任**（サービスアカウントが各メンバーとして読む）。設定手順は docs/meet-archive-ops.md 5-b。
委任が入れば `MEET_ARCHIVE_IMPERSONATE=1` でカレンダー取得も含めてスクリプト単独で完結し、共有依頼が不要になる。

## 構成

```

config/meet-archive-manifest.json      状態（処理済みID・チャンク一覧・プレースホルダ・直近実行 lastRun）
.claude/skills/meet-collector/SKILL.md 日次ルーティンの手順
docs/meet-archive-ops.md               運用・障害対応・管理者設定
```

## 使い方

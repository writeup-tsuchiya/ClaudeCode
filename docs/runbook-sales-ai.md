## 1. 全体像

```
Google Drive「営業AI」＝ 正本（設定と記録の置き場）
        │
        ├─ クラウド Routine（平日 朝8:00 / 夜19:00）… PCが閉じていても動く
        ├─ 補完 Routine（9:10 / 10:10 / 19:10）… 台帳を見て未完了のときだけ動く
        └─ 商談ログ処理（手動）… 【商談ログ】を貼り付けたときだけ動く
```

すべての出力は **下書きまで**。送信・投稿は担当者が行う。

## 2. Routine の登録手順（claude.ai の画面から行う）

### なぜ画面から登録するのか

Claude Code のセッション内から Routine を作ると、
**Gmail / カレンダー / Drive / Slack への接続が引き継がれない**。
接続なしの Routine は毎朝起動しても何もできずに終わる。
接続付きの Routine を作れるのは claude.ai の Routines 画面だけ。

### 手順

1. ブラウザで claude.ai を開く
2. 左メニューの **Routines** を開く
3. **New routine** を押す
4. 下の表のとおりに入力する
5. 接続（Connectors）で **Gmail / Google Calendar / Google Drive** を有効にする
   （夜の処理だけ **Slack** も加える）
6. 保存する

### 登録する Routine 一覧

| 名前 | cron（UTC） | JST | 中身 |
|---|---|---|---|
| 営業AI 朝の基本処理 | `0 23 * * 0-4` | 平日 08:00 | prompts/morning.md |
| 営業AI 朝の補完 | `10 0 * * 1-5` | 平日 09:10 | prompts/morning-fallback.md |
| 営業AI 朝の追加確認 | `10 1 * * 1-5` | 平日 10:10 | prompts/morning-fallback.md |
| 営業AI 夜の基本処理 | `0 10 * * 1-5` | 平日 19:00 | prompts/evening.md |
| 営業AI 夜の補完 | `10 10 * * 1-5` | 平日 19:10 | prompts/evening-fallback.md |

**曜日がずれている理由**: JST は UTC+9。朝8時 JST は前日23時 UTC なので、
「月〜金 JST」は UTC では「日〜木」= `0-4` になる。
夜19時 JST は同日10時 UTC なので `1-5`（月〜金）のままでよい。

### 既存 Routine の整理

`Sales morning briefing`（英語のプロンプト、cron `0 23 * * 0-4`）が
すでに登録されている。新しい朝の処理と同じ時刻に動くため、
**どちらか一方を無効化する**こと。両方動かすと朝の報告が2通届く。

## 3. Claude Desktop の scheduled tasks（完全ローカル補完）

クラウドが全面的に止まった場合の備え。必須ではない。

1. Claude Desktop を開く
2. 設定 → Scheduled tasks → 新規作成
3. 平日 09:10 / 10:10 / 19:10 を指定
4. 対応する prompts/*.md の中身を貼り付ける
5. Desktop 側でも Gmail / カレンダー / Drive / Slack を接続しておく

PC が起動していないと動かない。クラウドと重複しても、
台帳を見て未完了のときだけ動くので二重処理にはならない。

## 4. 重複防止のしくみ

識別キー = `実行日 __ 対象識別情報 __ 処理種類`

`99_処理台帳` に 1処理1ファイルで記録する。
Drive コネクタは既存ファイルの本文に追記できないため、追記方式は使わない。

処理開始前に必ず次を実行する。

```
parentId = '1IH8Ps9K9fCjPEnchDzaeMAgpEtuOnavu' and title contains '<キー>'
```

完了ファイルがあれば **何も作らず静かに終了**（通知もしない）。

動作確認済み（2026-08-17）:
- `2026-08-17__朝__完了` で検索 → 1件ヒット → 補完処理は起動しない
- `2026-08-17__夜__完了` で検索 → 0件 → 夜の処理は通常どおり動く

## 5. トラブルシュート

| 症状 | 原因 | 対処 |
|---|---|---|
| 朝、何も届かない | Routine に接続が付いていない | claude.ai の Routines 画面で接続を確認 |
| 下書きが2通できる | 朝の Routine が2つ動いている | 古い `Sales morning briefing` を無効化 |
| 台帳に記録が無い | 途中で失敗した | `__失敗` ファイルを確認。補完処理が続きを実行する |
| Slack 下書きが自分の画面に無い | Slack の接続先が別アカウント | 接続を相澤アカウントで繋ぎ直す |

## 6. やらないこと

- メール送信・Slack 投稿の自動化（下書きまで）
- 顧客リストへの書き込み
- カレンダー予定の変更、権限・共有設定の変更
- 恒久的な定時処理に `/loop` を使うこと（セッション依存で期限があるため）

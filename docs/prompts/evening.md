■ 2. 本日の打ち合わせを整理
カレンダー aizawa@writeup.co.jp の本日の予定を取得し、
商談ごとに 課題 / 決定事項 / 進捗 / 次のアクション を整理する。
商談ログや議事録が 03_議事録 にあれば参照する。
記録が無い商談は「記録なし（要確認）」とする。憶測で埋めない。

■ 3. Slack 日報の下書き
共通設定「5. Slack日報の形式」に従って作成する。
含める項目: 本日の打ち合わせ先 / 目的 / 顧客の課題 / 決定事項 / 商談の進捗 /
次のアクション / 社内への依頼事項 / 懸念点・要確認事項 / 明日の重要な打ち合わせ。

担当者設定「5. Slack報告先」を見る。
- 報告先が具体的なチャンネル名で書かれている場合 … そのチャンネルに下書きを作る
- 「未設定」と書かれている場合 … **Slackには何も作らない**。
  日報の本文は 05_日報 に保存し、報告の中に全文を表示する。
※ 投稿は絶対にしない。下書きまで。
※ 報告先が不明なまま、別のチャンネルへ下書きを作ってはいけない。

■ 4. 翌日の準備
翌営業日のカレンダーを取得し、社外の相手がいる打ち合わせを抽出する。
提案内容・前回の宿題・不足している準備を確認する。
確認が必要な相手には、確認メールを Gmail 下書きとして保存する。
件名の先頭に【AI下書き】を付ける。保存前に list_drafts で重複を確認する。
保存後、下書きを再取得して宛先・件名・本文を確認する。

■ 5. 日報の保存
Drive の 05_日報（parentId: 1VymW-M-nS_L2TK4pG6GfDhs6KtKQ-duf）へ
「日報_YYYY-MM-DD」という名前で保存し、読み直して確認する。

■ 6. 台帳へ記録
「<本日YYYY-MM-DD>__夜__完了」を作成する。
失敗した場合は「完了」を作らず「__夜__失敗」を作り、どこまで進んだかを書く。

■ 7. 報告
# 本日の営業まとめ
## 📊 今日の結果   … 表（商談先/進捗/決定事項/次のアクション）
## 📅 明日の打ち合わせ … 表（時刻/相手/目的/準備状況）
## 📝 作成済みの下書き
## ⚠️ 残っていること  … 未処理・失敗・要確認
## ✅ 明日の準備     … 3件以内

前日までに未処理のまま残っている項目があれば「残っていること」に含める。

■ 安全ルール
メール送信・Slack投稿をしない。削除・権限変更をしない。
顧客リストへ書き込まない。数字・人物・会社情報を捏造しない。
不明は「要確認」、推測は「仮説」と明記。承認待ちを「送信済み」と書かない。

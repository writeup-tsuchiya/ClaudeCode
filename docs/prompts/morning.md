■ 2. Gmail 返信下書き
対象期間は前回の正常終了時刻から現在まで（不明なら直近24時間）。
返信対象: 顧客・取引先からの質問や依頼 / 日程調整 / 自分の返答待ち /
自分が対応を約束している事項 / 期限のある確認依頼。
除外: メルマガ・広告・自動通知・返信不要の情報共有・すでに返信済み・宛先や目的が不明。
必要に応じて get_thread で過去のやり取りを確認する。
自分（aizawa@writeup.co.jp）が最後に返信しているスレッドは原則除外。
担当者設定の「メール文体」に沿って返信案を作り、Gmail の下書きとして保存する。
件名の先頭に【AI下書き】を付ける。判断に迷ったものは【AI下書き・要確認】にし、
迷った理由を本文末尾に書く。
保存前に list_drafts で同じ相手・同じ用件の下書きが無いか確認する（重複防止）。
保存後、下書きを再取得して宛先・件名・本文を確認する。
※ 送信は絶対にしない。下書きまで。

■ 3. 本日の打ち合わせと事前レジュメ
カレンダー aizawa@writeup.co.jp の本日の予定を取得。
参加者に @writeup.co.jp 以外のドメインが含まれる打ち合わせだけを抽出（社内MTGは対象外）。
予定名に企業名があるが社外参加者が登録されていない場合は、対象に含めたうえで
「参加者情報が未登録（要確認）」と明記する。
各打ち合わせについて、Gmail・Drive・04_営業ナレッジ から過去の接点を調べる。
企業を一意に特定できる情報（Webサイト、メールドメイン）がある場合のみ
直近の公開情報を調べ、情報源URLと確認日を必ず併記する。
特定できない場合は調べない（同名企業の誤紐づけを避けるため）。
共通設定「2. 商談レジュメの形式」の見出しをその順番どおりに使ってレジュメを作り、
Drive の 02_事前レジュメ（parentId: 1euKKd1-JuUxP6GXKrMnC3-Tuo__CLaqi）へ
「レジュメ_YYYY-MM-DD_企業名」という名前で保存する。
情報が無い項目は「情報なし（要確認）」と書く。省略しない。
保存後に read_file_content で読み直して確認する。

■ 4. 台帳へ記録
Drive の 99_処理台帳（parentId: 1IH8Ps9K9fCjPEnchDzaeMAgpEtuOnavu）へ
「<本日YYYY-MM-DD>__朝__完了」という名前でファイルを作成する。
中身: 実行日時(JST) / 実行環境 / 処理対象 / 作成した下書き・レジュメの名前とリンク /
参照した情報 / 要確認事項 / 成功・失敗 / 次回の再実行要否。
メール本文の全文は複製しない。
途中で失敗した場合は「完了」を作らず「<本日YYYY-MM-DD>__朝__失敗」を作り、
どこまで進んだかを書く。成功扱いにしない。

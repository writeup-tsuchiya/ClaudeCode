# 商談ログ分析Routine：スプシ書き込みの構成と設定手順

Routine「Google Drive folder review」（商談ログ分析 → スプレッドシート追記 → Slack通知）用のセットアップ手順。

## なぜGASを挟むのか

Routineに繋がっているGoogleコネクタは **Gmail / Calendar / Drive** の3つで、Driveのツールは以下しかない。

| できること | ツール |
|---|---|
| ファイル検索 | `search_files` / `list_recent_files` |
| 中身を読む | `read_file_content` / `download_file_content` |
| ファイルを新規作成 | `create_file` |
| ファイルを複製 | `copy_file` |

**既存スプレッドシートの行を追記・更新するAPIが無い。** これがこれまでの
「Google Sheetsへの書き込み権限を持つ接続がないため自動入力ができませんでした」というエラーの正体で、
Routineのプロンプトをどう直しても解消しない。

そこで、スプレッドシート側に追記用のWeb APIを立てて、RoutineからHTTPSで叩く構成にする。

```
Routine（毎時）
   │  Drive: 各担当のフォルダから新着ログを検索・読み込み
   │  分析（Aヨミ／失注ステータス／商談評価／次回アクション）
   │
   ├─ GET  ?action=processed   → 追記済みfileId一覧を取得して二重分析を防ぐ
   ├─ POST /                   → 担当者タブに1行追記（GAS側でも fileId 重複排除）
   └─ Slack: チーム浦嶋-aiセールスch に全員分まとめて通知
```

- 実体は `gas/shodan-review-api.gs`
- 実行はスプレッドシート所有者の権限（＝アカウントを新規に作らない、鍵ファイルを持ち回らない）

## デプロイ手順（初回のみ・10分程度）

1. 追記先スプレッドシート（`1t7pVp895kKB0vWWHbq-h_hfDAp0HkW5oc1cW20HeCtQ`）を開く
2. **拡張機能 → Apps Script** を開く
3. `コード.gs` の中身を全部消し、`gas/shodan-review-api.gs` の内容を貼り付けて保存
4. 左メニュー **プロジェクトの設定 → スクリプト プロパティ → プロパティを追加**
   - プロパティ: `API_TOKEN`
   - 値: 推測されない文字列（例: `openssl rand -hex 24` の出力。手元で作れなければこちらで生成します）
5. 右上 **デプロイ → 新しいデプロイ → 種類の選択「ウェブアプリ」**
   - 説明: `商談ログ分析 追記API`
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/AKfy.../exec`）を控える
7. 疎通確認（URLとトークンを差し替えて実行）

   ```bash
   curl -sL "https://script.google.com/macros/s/XXXX/exec?action=ping&token=YYYY"
   # => {"ok":true,"spreadsheetId":"1t7pVp895kK..."}
   ```

### アクセス「全員」について

Routineは認証情報を持たないHTTPクライアントとして叩くため、ウェブアプリは「全員」で公開する必要がある。
守りは `API_TOKEN` の一致のみなので、

- URLとトークンは社外に出さない（Slackの公開チャンネルに貼らない）
- このエンドポイントは**追記と、追記済みfileIdの取得**しかできない。スプシの中身を読み出すAPIは生やしていない
- 漏れた疑いがあればスクリプトプロパティの `API_TOKEN` を変えるだけで即無効化できる（旧トークンは弾かれる）

### URLとトークンの置き場所

Routineのプロンプトに直書きせず、環境変数に入れるのを推奨。

- claude.ai/code → 該当の環境設定 → 環境変数に `SHODAN_API_URL` / `SHODAN_API_TOKEN` を追加
- 直書きする場合、値はトリガー設定に保存され、アカウント所有者以外からは見えない

## コードを変更したとき

Apps Scriptは保存しただけでは公開版が変わらない。
**デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン「新バージョン」→ デプロイ** で更新する（URLは変わらない）。

## スプレッドシートの構成

担当者ごとにタブが自動生成される（タブが無ければAPI側で作成＋ヘッダー装飾＋1行目固定）。

| 列 | 内容 |
|---|---|
| 分析日時 | Routineが分析した日時 |
| 商談日 | ログから読み取った商談実施日 |
| 担当者 | タブ名と同じ。フィルタ用に列にも持つ |
| 会社名 | 商談相手 |
| Aヨミ | 受注見込み |
| 失注ステータス | 失注/継続/不明など |
| 商談評価(点) | 点数 |
| 改善点 | 評価の根拠と改善提案 |
| 次回アクション | 次にやること |
| ログファイル名 / ログURL | 元ログへの導線 |
| fileId | 重複排除キー（列は非表示） |

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| `{"ok":false,"error":"トークンが一致しません"}` | スクリプトプロパティ `API_TOKEN` とRoutine側の値がずれている |
| `スクリプトプロパティ API_TOKEN が未設定です` | 手順4を実施していない |
| curlが302を返して中身が返らない | `curl -L` を付ける（GASは必ずリダイレクトする） |
| HTMLのログインページが返る | デプロイのアクセス範囲が「全員」になっていない |
| 同じ商談が二重に入る | GAS側は `fileId` で弾く。同一商談でファイルが2つある場合はファイル名側の重複（コピー等）を疑う |
| 追記はされるがタブが増えない | Routineが送る `owner` が空。`config/shodan-review.json` の担当者名とフォルダの対応を確認 |
